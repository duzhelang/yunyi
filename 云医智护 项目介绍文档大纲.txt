## 4. 项目背景与需求分析

### 4.1 行业背景
- 糖尿病患病率数据（全球、中国，IDF糖尿病地图数据）
- 传统筛查痛点：效率低、数据分散、缺乏个性化、黑盒模型不可解释
- 医疗AI监管趋势：可解释性（XAI）成为刚需

### 4.2 用户角色与需求
- **普通用户**：自助风险检测、健康档案管理、AI咨询、每日打卡
- **医生/诊断员**：患者数据深度分析、群体统计、诊断辅助、个体洞察
- **运维人员**：故障报修处理、工单管理
- **管理员**：模型训练与部署、权限管理、数据集管理、系统配置

### 4.3 项目目标
- 构建"预测→解释→管理→分析"全流程闭环
- 实现可解释AI（SHAP + MC Dropout不确定性估计），让黑盒透明化
- 打造生产级前后端架构（Vue3 + Spring Boot 3.3.5 + Python子进程），支持快速迭代
- 数据库驱动动态路由 + RBAC权限，零代码新增页面

## 5. 技术架构

### 5.1 整体架构图
- **五层架构**：展示层（Vue 3.4）→ 网关层（JWT拦截器）→ 业务层（Spring Boot 3.3.5）→ AI引擎层（Python 3.12）→ 数据层（MySQL 8.0 + Redis）
- 前后端分离、RESTful API（169个端点）
- Python子进程模式由后端按需调用（UsePythonUtils工具类）

### 5.2 技术栈说明

| 层级 | 技术 | 选型理由 |
|------|------|----------|
| 前端 | Vue 3.4 + Element Plus 2.4 + ECharts 5.6 + Pinia 2.1 + Vite 5 | Composition API灵活，15个Composables复用，体积相对Vue2减少87% |
| 后端 | Spring Boot 3.3.5 + MyBatis-Plus 3.5.9 + JWT (Auth0 java-jwt 3.10.3) + Java 17 | 最新LTS，轻量ORM，无状态认证 |
| AI引擎 | Python 3.12 + PyTorch 2.11 + SHAP 0.46 + Pandas | 三层全连接网络，SHAP可解释性，MC Dropout不确定性估计 |
| AI大模型 | 智谱GLM-4 / DeepSeek / Kimi / MiMo | OpenAI兼容接口统一调用，后端降级保障 |
| 数据 | MySQL 8.0 + Redis + Spring Cache | 25张业务表，关系型+缓存双引擎 |
| API文档 | SpringDoc OpenAPI 3 (springdoc-openapi 2.2.0) | 替代springfox，原生支持Spring Boot 3 |
| 部署 | Docker + Nginx | 容器化，支持横向扩展 |

### 5.3 数据流图
- 用户输入 → API Gateway → Controller → Service → UsePythonUtils → Python子进程 → 模型预测 → 结果回写DB → 前端ECharts可视化

## 6. 核心功能模块

### 6.1 风险预测与可解释AI
- **单条预测**：8项指标输入 → SinglePredictController → predict_single.py → 概率 + 风险等级 + 置信区间（MC Dropout 15次迭代）
- **批量预测**：CSV上传 → predict.py → 批量推理 → JSON结果导出
- **SHAP可视化**：特征重要性柱状图、瀑布图、雷达图（9种图表类型）
- **不确定性估计**：MC Dropout → 95%置信区间，量化预测可靠性
- **模型热切换**：sys_model_version表管理，管理员激活不同版本

### 6.2 多模型AI智能问诊
- **模型切换**：智谱GLM-4 / DeepSeek / Kimi / MiMo，统一OpenAI兼容接口
- **强身份约束**：糖尿病专科医生角色扮演
- **TTS语音播报**：MiMo音色定制，适配老年用户
- **上下文感知**：从预测结果页携带数据跳转DiabetesChat，回答更精准
- **前端体验**：useChat组合式函数实现打字机效果、消息管理、自动滚动

### 6.3 全周期健康管理
- **健康档案**：11项生理指标 + 生活方式数据录入，趋势图（血糖/血压/体重/DPF历史）
- **每日打卡**：饮食/运动/用药/血糖四项任务，useDailyCheckin进度可视化
- **诊疗档案**：就诊记录、诊断结论、治疗方案，软删除 + 自动淘汰（保留最近5次）
- **风险快检**：快速评估，结果自动存档至user_health_profiles
- **健康计划**：useHealthPlan自动生成一周健康计划（风险评估 + Mock回退）
- **控糖食谱**：useRecipe根据饮食偏好生成食谱（安全HTML处理）

### 6.4 数据看板与群体分析
- **个人报告**：历史趋势、指标对比、风险变化
- **群体分析**：年龄分布、性别/风险占比、BMI-血糖散点图、风险热力图
- **个体洞察**：SHAP归因分析、相似病例余弦匹配
- **持久化**：analysis_record表存储分析结果，支持历史查询
- **导出功能**：Excel / PDF报告下载

### 6.5 AI模型管理（MLOps实践）
- **训练集管理**：CSV自动扫描入库、数据质量检测（质量等级/样本数/列信息）
- **在线训练**：超参数配置（lr/epochs/batch_size）、@Async异步任务、进度实时推送
- **增量训练**：incremental_train.py支持加载已有权重、复用预处理器、冻结层级选择
- **模型版本管理**：注册（file_path + scaler_path + encoder_path）、激活部署、6项评估指标（accuracy/loss/recall/precision/f1/auc）、混淆矩阵
- **对外统一接口**：激活模型自动供单条/批量预测调用

### 6.6 运维中心
- **维修工单系统**：提交→指派/认领→处理→完成→评价→关闭 全闭环
- **工单状态机**：pending → assigned → processing → completed → closed（支持reopen）
- **处理日志**：sys_repair_log记录每次操作
- **满意度评价**：1-5星评分 + 评价内容

### 6.7 教育资源
- **科普文章**：diabetes_education表，HTML富文本内容，分类管理
- **健康视频**：diabetes_video表，视频播放（video.js），类型筛选
- **社区留言**：education_comment表，用户互动

### 6.8 权限与安全
- **RBAC模型**：4种角色（管理员/医生/用户/运维），sys_role_menu三级控制
- **JWT无状态认证**：Auth0 java-jwt，Token含用户密码签名防篡改
- **数据库驱动路由**：sys_menu表动态生成前端路由，零代码新增页面
- **API安全**：密钥环境变量注入，JwtInterceptor拦截器统一校验
- **数据隔离**：通过Token提取userId，用户只能查看自己的数据

## 9. Python算法层设计

### 9.1 模型架构
- 三层全连接神经网络（DiabetesNet）：fc1(8→64) → fc2(64→32) → fc3(32→1)
- Dropout正则化（0.2）+ ReLU激活 + Sigmoid输出

### 9.2 训练能力
- **新建训练**（train.py）：从头训练，输出.pth + scaler + encoder + 指标JSON
- **增量训练**（incremental_train.py）：加载已有权重、复用预处理器、冻结层级选择（none/fc1/fc1+fc2/all-hidden）
- **6项评估指标**：accuracy / loss / precision / recall / F1 / AUC + 混淆矩阵

### 9.3 推理能力
- **单条预测**（predict_single.py）：8项特征 → 概率 + MC Dropout置信区间 + SHAP归因
- **批量预测**（predict.py）：CSV文件 → 逐行推理 → JSON结果
- **AI对话**（diabetes_chat.py）：OpenAI兼容SDK，支持4个大模型服务商

### 9.4 后端集成
- UsePythonUtils工具类：callPythonAndGetOutput / callPython / callPythonWithCallback
- 30秒超时控制、UTF-8编码环境变量、子进程模式

## 11. 创新点与难点攻克

### 创新点

| 创新点 | 说明 |
|--------|------|
| 可解释AI (XAI) | SHAP值瀑布图 + 特征重要性 + MC Dropout不确定性估计，符合医疗AI监管趋势 |
| MLOps实践 | 模型版本管理 + 热切换 + 增量训练 + 冻结层级，完整的模型资产化流程 |
| 多模型编排 | 统一OpenAI接口调用智谱/DeepSeek/Kimi/MiMo，后端配置热切换 |
| Vue3全量重构 | 15个Composables组合式函数，解决50+兼容性问题，体积减少87% |
| 数据库驱动路由 | sys_menu表动态生成前端路由，零代码新增页面，RBAC权限隔离 |
| 子进程隔离 | Python以子进程模式运行，30秒超时保护，避免僵尸进程 |
| 全周期管理 | 预测→解释→建档→打卡→诊疗→分析 完整健康闭环 |

### 难点攻克
- Element UI → Element Plus破坏性变更适配（图标系统重构、DOM结构变化、样式类名更新）
- Python子进程超时控制 + 异步并行调用，避免僵尸进程
- 动态路由守卫无限重定向修复（引入重试标记防死循环）
- 大文件分片上传 + 断点续传
- SHAP可视化在前端9种图表类型的统一渲染方案
